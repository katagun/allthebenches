# GPT-6.1 Sol frontier evidence audit

Snapshot date: 2026-10-17. This fragment adds 55 reviewed observations for the canonical `gpt61_sol` model. It adds no model or lab entities and does not modify the canonical dataset. The fragment is intended to be merged with `data/curated/dataset.json`; it reuses the canonical `gpt61_sol_unknown`, `gpt61_sol_low`, and `gpt61_sol_max` configuration IDs. All numeric values below were transcribed from the source named in each observation. No value was copied from GPT-6 Astra or inferred from a plotted bar.

## Coverage

The fragment contains 40 safety observations, 8 agent/search observations, 6 reasoning observations, and 1 coding observation. The four reasoning results from the OpenAI system card are HealthBench length-adjusted scores; the other two are OpenAI's low-effort factual-error rate and Surge AI's GDP.pdf leaderboard score. The coding result is OpenAI's Internal Research Debugging Evaluation. The agent results are Parallel's search-enabled and search-disabled profile results. The safety results cover OpenAI's production challenging-prompt, under-18, agentic safe-completion, image-input, biology/chemistry capability, cyber capability, broken-search, and coding-deception evaluations.

The fragment includes numeric public evidence for GPT-6.1 Sol in math-adjacent and coding/agentic work only where the source supplies exact results. It does not invent a general math score. It does not assign scores to DeepSWE, OSWorld, Terminal-Bench Science, or AutomationBench from launch-page deltas.

## Metric and configuration handling

OpenAI Tables 1–4 state safe-completion metrics as rates from 0 to 1; the fragment preserves those values and units rather than converting them to percentages. The HealthBench rows are length-adjusted score points, with the unadjusted score and mean response length retained in observation setup. Effort is not stated for those rows, so they use the canonical unknown-effort configuration. OpenAI explicitly identifies maximum reasoning effort for ExploitBench (PDF p.42), so only that observation uses `gpt61_sol_max`. The launch-page factuality value explicitly says low effort and uses `gpt61_sol_low`. Surge explicitly names max effort and uses `gpt61_sol_max`. Parallel does not state a matching GPT-6.1 reasoning effort, so its rows use the unknown-effort configuration.

The two alignment stress-test metrics added after source review are kept distinct: Broken Search Tool is 2.08% (PDF p.17, lines 534–537), and Coding Deception misrepresentation is 1.50% (PDF p.16, lines 526–531). Both use the unknown-effort configuration because those paragraphs do not state GPT-6.1's effort. The source says the deceptive-interaction tasks were deliberately selected to elicit dishonest behavior and that their rate should not be treated as the true production rate. Neither value is a general factuality or coding-accuracy score.

The high/critical biology and chemistry capability results retain their native metrics (`%`, `ρ`, `R²`, `score`, and `NLL`); they are not normalized into a shared score. Cyber capability results are reported as percentages. OpenAI warns the ExploitBench result may be inflated by exposure to historical vulnerabilities (PDF p.42), and its system-card testing setup does not represent normal production use. These are capability-evaluation results, not estimates of real-world incident rates.

## Exclusions and known gaps

- DeepSWE v1.1: OpenAI's launch page describes relative performance versus GPT-6 Sol but gives no absolute GPT-6.1 score. The evaluator leaderboard snapshot checked on 2026-10-17 predates GPT-6.1's launch and contains no GPT-6.1 row. No Astra or Sol score is transferred to GPT-6.1.
- OSWorld 2.0: the launch page gives relative deltas, not an absolute GPT-6.1 value. The checked evaluator page did not expose a GPT-6.1 result.
- Terminal-Bench Science 0.1 and AutomationBench: the launch page gives relative claims only; the checked current AutomationBench listing had no GPT-6.1 row. No absolute score is derived from those deltas.
- KernelGen 1P: the card describes comparative performance but the accessible text contains no unambiguous numeric result. No chart height was read as a score.
- OpenAI chart-only evaluations: excluded where text extraction did not yield a visually unambiguous numeric GPT-6.1 value. The fragment does not turn comparisons, trends, or qualitative claims into numbers.
- Third-party model aggregators: excluded where entries were estimates, lacked a clear exact release mapping, or did not expose a sufficiently specific evaluator protocol/source locator.
- Parallel leaderboard settings can differ in reasoning budget and token limits across models; its rows support a within-listing search/no-search comparison, not a controlled model-only comparison.

The coverage gaps in the JSON record these missing exact agent-evaluation values and chart/aggregator exclusions for downstream UI. All included observations have a source locator, an explicit reporting relationship, and a setup note that preserves known effort/protocol details or marks them unstated.

## Added coding-agent result: sudo L7

Surge AI's [sudo L7 leaderboard](https://surgehq.ai/benchmarks/sudo-l7) lists “GPT 6.1 Sol (Max reasoning) [Codex]” at **28.9%** (leaderboard row, accessed 2026-10-17). The linked [benchmark explanation](https://surgehq.ai/blog/sudo-l7) describes 60 tasks authored by professional software engineers, intended to test software-engineering judgment across unfamiliar systems, and expert-authored rubrics across eight dimensions; grader models use unit tests, static analysis, and other executable checks as evidence where appropriate. The observation records the exact live leaderboard value and max-effort/Codex setup. The listing does not show aggregation details, so this is a benchmark score rather than a claim of ordinary unit-test pass rate. The explainer rounds the Sol result to roughly 30%; the exact leaderboard snapshot is used here. This addition brings the fragment to 56 observations, including 2 coding-category results.
